# puppy-studio — 小狗 IP 一键工作流

一句指令触发本项目的完整规范流程。目标是让用户不必每次重复交代规矩——所有规则都在项目文档里，本 Skill 的第一步就是强制读取它们。

## 第 0 步（强制，不可跳过）：读取项目规则

在理解用户意图之前，**先读**以下文件，按顺序：

1. `AGENTS.md` — 总纲与行为准则（最高优先级）
2. `HANDOFF.md` — 交接：项目现状、已定决策、待办
3. 根据意图追加：
   - 生成任务（视频/图片）→ `PRODUCTION.md` + `PROJECT.md` + `PREFERENCES.md`
   - 剧情/脚本 → `PROJECT.md` + `PREFERENCES.md`
   - 产品/规划 → `PRD.md`

读取后，以这些文件中的规则为准。任何与对话记忆冲突的地方，以文件为准。

## 核心事实（来自 AGENTS.md，不得更改）

- 三个角色：**问天**（主角）、**炼狱**（竞争对手）、**白城**（大佬/权威）
- 关系：问天 ↔ 炼狱 对抗；白城 层级在两者之上
- 默认画幅：16:9 横屏；默认语言：简体中文
- 用户偏好：先捋清楚再动手、接受合理默认值、但关键参数必须先确认、授权后一次到位

## 完整流程（六步）

### 第 1 步：意图识别

判断用户这次要什么，互斥单选：

| 意图 | 判断依据 | 后续路径 |
|---|---|---|
| 视频生成 | 会动的内容、视频、短片 | 走第 2–6 步 + 视频生成领域 skill |
| 图片生成 | 定妆图、封面、表情包、分镜图 | 走第 2–6 步 + 图片生成领域 skill |
| 剧情脚本 | 故事、剧情、剧本 | 走剧情创作流程（不需要生成调用） |
| 文档/代码 | 改规范、改文档、仓库操作 | 直接执行，不走生成流程 |

意图判断错了后面全错。拿不准就问用户。

### 第 2 步：生成前确认（生成类任务必做）

**任何 AI 生成调用前**，用提问让用户确认：

1. **产出什么、多少个** — 涉及多个资产时要说明规模，并给出更轻的备选
2. **本次规格** — 画幅、尺寸、时长，包括默认值也要展示（写在提问正文里，不要只放选项描述）
3. **用到的素材** — 参考图、角色锚点图、上一轮定稿；没有就说明是纯文字生成

有合理默认值的直接采用并展示，但上述三类关键参数不许猜。用户点头后才进入第 3 步。

### 第 3 步：建画布

用户同意后、发起生成前：如果没有画布，先建一张空画布并打开；已有画布就不要重复创建。

### 第 4 步：生成

- **有素材就必须用素材**：角色锚点图、用户参考图、上一轮定稿都是硬约束，不得退化成纯文字。
- 视频提示词写清四件事：主体动作、镜头运动（一个镜头一种）、光线氛围、结束状态。
- 一个镜头讲一件事；多分镜拆成多条视频，不硬塞成一条。
- 只用项目规定的生成路径，失败时先查后端任务状态，不重复发起。
- 每拿到一件产物，**立刻写进画布**。

### 第 5 步：验收

- 逐件检查：本地文件是否拿到、实际时长/画幅是否与确认一致、角色是否正确、是否都在同一画布。
- 成套检查：画幅统一、角色一致性、有无重复产物。
- 如实写检查结论；无法确认的事标为"无法确认"；不合格不自动重做，交给用户决定。

### 第 6 步：写回交接

任务结束后必须更新 `HANDOFF.md`：

- 本次做了什么、产出了什么
- 新增/变更的决策（尤其是角色形象、锚点图路径、风格方向）
- 新的待办事项
- 踩过的坑

涉及角色锚点图或固定描述的更新，同步写进 `PROJECT.md`。

## 剧情脚本任务（不走生成调用）

1. 读 `PROJECT.md`，确认角色设定与关系。
2. 按用户要求写剧情，遵守：问天是主角、炼狱是对手、白城是大佬/权威，名字和关系不得更改。
3. 剧本是文字资产，写入项目文件（如 `stories/` 目录），不要当成视频交付物。
4. 更新 `HANDOFF.md`。

---

## 硬性禁止

- 跳过第 0 步直接干活
- 改错/写错角色名字，或混淆三者身份关系
- 未经确认发起会计费的生成
- 有参考图却走纯文字路径
- 把多分镜塞成一条视频、把脚本当视频交付
- 自动重做不合格产物
- 向用户暴露工具名、模型标识、任务 id
- 断言"画面流畅""运镜到位"这类无法确认的结论
